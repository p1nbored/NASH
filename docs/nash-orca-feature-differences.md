# NASH 与 Orca 原生的功能差异

对照本仓库采用的 Orca `61de2d8ec8598803c0177aea9613444f6d2ef79d`，本文描述当前源码；已交付版本见[发布记录](releases.md)。这不是对互联网最新 Orca 的实时比较。

以下区分新增、改动、删除和禁用；“已实现”不代表所有真实 CLI、账户和远程场景都已完成端到端验证。使用方法见[操作指南](nash-operations.md)，实现边界见[架构说明](architecture-direction.md)。

## 新增

| 功能 | NASH 的行为 |
|---|---|
| 任务分类器 | 判断是否委派及任务类型；当前使用 Clef，不承担规划或模型选择。 |
| 按任务类型路由 | 选择 CLI、具体模型和推理强度，执行前检查可用性。 |
| 协调者配置 | 新运行可选 Claude Code 或 Codex；既有会话接管时保留当前 CLI、模型与上下文。 |
| Workbench | 应用内的请求、运行、子任务、消息、权限及验证结果入口。 |
| Dot 接入与接管 | 本地接口和私有远程 MCP 邮箱；可启动新协调者，或显式选择已有本地运行接管。 |
| 分层权限审批 | Claude/Codex/AGY 普通子任务由协调者审核；协调者普通权限由 Dot 审核；关键权限需要用户确认。 |
| 访问上限与独立复核 | 请求/任务保存只读或工作区可写上限；支持独立复核及无法确认结果的豁免/拒绝。 |
| Windows AGY 账户适配 | 增加 Windows Credential Manager 与私有文件权限适配；真实双账户切换仍未实测。 |

分类、路由和权限规则建立在原生运行、任务、派发、终端及消息机制上。其他分类模型尚未接入；AGY 当前支持 worker，不支持接管为协调者。

## 改动

| 功能 | 当前行为 |
|---|---|
| 产品身份 | NASH 名称、应用 ID、数据目录、CLI、图标及独立仓库；问题与发布归 NASH。 |
| 界面 | Paper 主题、语义样式、字体分工、随包 CJK 字体和六语言文案；保留原生组件体系。 |
| 设置与引导 | 独立 Dot 和任务路由分类；引导按真实功能状态完成。 |
| 协调者机制 | 恢复原生协调者/worker；现有 CLI 可继续协调，Dot 新任务也可自动启动协调者；界面统一称“协调者”。 |
| 路由与审查者编辑 | 模型下拉框读取所选 CLI 的模型列表，支持刷新和按 ID 去重；CLI/模型决定推理等级；Claude 工作流可选模型和思考等级，CLI 固定。 |
| 智能体权限模式 | 新增 Auto 智能审核，保留 Yolo 和手动；选择会持久化到执行主机，切回手动会阻断未完成的智能审批。Auto 不表示自动选择模型。 |
| 分类器命名 | Clef 的显示名称改为“分类器”，凭据与验证实现仍为 Clef。 |
| 任务执行与上下文 | Codex/AGY 新委派复用原生 worker、任务上下文、消息和停止机制；TaskSpec 补入输出、验收与约束。 |
| 路由任务的会话 | 手动模式下 Claude/Codex 的 task-start 复用原生会话偏好与审批，执行主机不支持时沿用原生终端回退。Auto 等其他模式继续使用终端 CLI worker；普通原生 worker-start 保留原生默认选择。 |
| 工作树与取消 | Git 写任务使用原生 child worktree；只读/文件夹任务沿用当前位置。停止未确认时保留状态；接管请求不会关闭用户原有 CLI。 |
| Dot 授权 | 控制权与原始请求来源分开记录；撤销或降低授权后，排队消息也停止投递；接管重试不启动第二个协调者。 |
| 消息与运行状态 | 消息使用原生串行队列和状态事件唤醒，保留一个共用的定时兜底；协调者归属读取原生绑定，重绑后不再显示旧接管关系。 |
| Hooks | 状态 hooks 的自动安装仍限 Claude；独立权限 hooks 支持 Claude/Codex/AGY，Codex 使用精确 hook 哈希信任。 |
| 语言 | 内部协调消息使用英文，工件语言按任务要求；不固定交付中文。 |
| 插件与平台 | 官方 catalog 与安全列表恢复 Orca 原生默认流程，只保留原生插件系统开关，删除 NASH 额外 opt-in；应用名称与数据目录仍为 NASH。保留 Windows/WSL 的身份、IPv4 与启动修复。 |
| 自动更新 | 恢复检查与下载入口，稳定版和 RC 使用 `p1nbored/NASH`，不使用另造的开发版仓库。 |
| 反馈与崩溃报告 | 恢复入口并打开 NASH GitHub Issue 草稿，由用户在浏览器审核、提交；不自动上传报告，也不把打开草稿标记为已发送。 |

原生 worker 完成不等于独立验证通过。AGY 的 sandbox 参数也不代表完整文件系统只读隔离。

更新、官方插件目录和报告入口的 NASH 禁用限制均已移除。自 `v1.4.218` 起发布包包含自动更新元数据；更早版本未启用更新源，需要先手动升级一次。

原生结构化审批当前没有分层审核所需的完整工具输入，因此 Auto 保留终端权限通道，没有新增审批桥。原生 decision gate 会结束派发并在确认后重新启用任务，不能等价替换独立验收；验收继续复用原生任务状态迁移和邮箱。

## 删除

部分删除项是后续撤销的 NASH 自建功能，不表示 Orca 原生曾有这些功能。

| 删除项 | 范围与保留部分 |
|---|---|
| GitHub Star 支持入口 | 删除首页/设置按钮、专用组件、搜索项和页面访问时的 Star 查询。底层已禁用的提示服务保留。 |
| 分类器“高级” | 删除高级说明、复制诊断、专用格式化/翻译及后端专用诊断输出。保留凭据、验证、阈值和失败/配额保护。 |
| 任务路由“高级” | 删除导入、建议审批、版本列表/回退界面及其后端操作、建议存储和生成逻辑。保留原子保存所需的内部版本、索引、哈希。 |
| 旧独立任务执行器 | 删除 Codex/AGY 独立执行、旧转录、结果文件回退、旧停止/恢复和进程记录路径；独立复核仍可使用 one-shot CLI。 |
| codex-plugin-cc harness | 删除该特定执行 harness；通用插件管理继续保留。 |
| 旧 NASH 兼容层 | 删除退休的 Dot/Workbench 协议、旧执行记录和快照补齐。权限 v2→v3 的已知迁移仍存在。 |
| 可执行文件固定 | 删除 executor-trust、二进制 hash 固定及重复启动验证，使用用户安装的官方 CLI。 |
| Clef 成本提示 | 删除产品中的 budget cap 和费用警告；实际分类与验证调用保留。 |
| 旧引导、品牌与语言字段 | 删除旧引导迁移、弃用参数、被替代的图标及固定交付语言字段。 |

## 禁用、隐藏或未提供

| 功能 | 当前状态 |
|---|---|
| Orca Account / Mobile 产品入口 | 界面与提示隐藏，代码保留；不包括开发用手机浏览器模拟器。 |
| 其他默认 Orca 云服务 | 默认登录、共享目的地、relay/mobile push 等仍关闭或未接通；独立端点配置另行控制。 |
| GitHub Star 弹窗/toast | 构建标记关闭，服务代码保留；与已删除的支持按钮区分。 |
| RSI | 导航隐藏，后端未完成；不显示虚构运行结果。 |
| 第二规划循环、GEPA、Recuris、Dream-RSI | 未作为当前产品的自主执行机制启用；研究代码或候选计划不等于交付功能。 |

构建开关见 [nash-build-flags.ts](../desktop/src/shared/nash-build-flags.ts)。默认云功能关闭不表示 Claude/Codex 等 provider 账户功能被关闭。

## 使用边界与历史纠正

- 已有协调者接管支持本地 Claude/Codex；没有独立 detach 命令。取消接管请求不会终止原有 CLI。
- 权限 hook 按各 CLI 的加载和信任规则生效，不自动重启已有会话；SSH/WSL 安装不在本版范围。
- 关键权限以脱敏摘要交给 Dot 请求用户确认；Dot 不能代替用户批准。
- 桌面 v1.4.215 已发布；远程接管所需的 Site bundle 尚未部署，见 [Dot 记录](dot-mcp.md#deployment-record)。
- “Claude 账户切换被删除”“配额只读 CLI”“Codex/AGY 总是只读或独立 headless”“固定 Claude 唯一协调者”“排除整个 Gemini 4 家族”“交付固定中文”均为已被取代的历史描述。
- 不再维护容易过期的文件级 CSV；需要逐文件比较时使用 Git diff。原生终端、编辑器、浏览器、Git/provider 和插件等保留功能不重复列为 NASH 新增。

完整测试、打包与真实场景未验证项集中在[发布记录](releases.md)，不在多份文档重复维护。

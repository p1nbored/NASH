# NASH 与 Orca 原生的功能差异

更新日期：2026-10-08。本文按用户能看到或使用的功能整理，包括此前已经形成的 NASH 差异和本轮修改。

对照基线是本仓库已经采用的 Orca `61de2d8ec8598803c0177aea9613444f6d2ef79d`，不是对互联网上最新版本的实时声明。本文依据[当前 checkpoint](nash-checkpoint-2026-10-06.md)、[决策记录](decision-log.md)、[架构方向](architecture-direction.md)及当前工作树核对。旧的[架构说明](architecture.md)包含历史实现，遇到冲突时以较新的决策和当前实现为准。

“已实现”表示源码与对应检查已落地，不表示已打包发布或已在真实 CLI、付费模型、远程服务上完成端到端验证。本轮功能及其部署、激活边界见第 5 节，验证范围见第 7 节。

## 1. 新增的功能

| 功能 | NASH 相对原生增加的行为 | 当前状态 |
|---|---|---|
| 任务分类 | 为结构化任务判断是否委派及任务类型，再交给路由选择执行目标；当前实现使用 Clef。 | 已有功能。分类器改为通用名称，不代表已经接入其他分类模型。 |
| 按任务类型路由 | 每类任务保存执行 CLI、具体模型与推理强度，执行前检查可用性；分类器不承担规划职责。 | 已有功能；本轮简化编辑方式和删除高级管理功能。 |
| 协调者配置 | 在设置中选择 Claude Code 或 Codex 作为新运行的协调者，并固定该运行的 CLI、模型与推理强度。 | 已有功能；修改设置只影响新运行。 |
| Workbench | 在应用中提交请求，查看 NASH 运行、任务、权限、消息和复核结果。 | 已有功能；底层运行、任务与派发状态沿用 Orca。 |
| Dot 接入 | 独立 Dot 设置、授权与工作区准入；支持请求提交、状态查询、跟进消息、权限与验证决定；提供本地入口及私有远程 MCP 邮箱。 | 已有功能；远程发布版本记录见 checkpoint。本轮接管既有运行另列在第 5 节。 |
| 请求与任务权限上限 | NASH 的任务与工作区保存只读或工作区可写上限，并传入原生启动与派发路径。 | 已有功能。AGY 的 sandbox 参数不能等同于完整文件系统只读保证。 |
| 验收与独立复核 | 对 NASH 会话内任务保留验收结果；独立复核可由配置的 CLI/model 执行，结果可以是通过、失败或无法确认。 | 已有功能；原生 worker 完成不会被伪装成 NASH 验证通过。 |
| 无法确认结果的处理 | Workbench 与 Dot 可查看待决定的验证，并作出豁免或拒绝；写入任务的处理仍需尊重其进程与工作树状态。 | 已有功能；真实远程与 CLI 联合验收不由单元测试替代。 |
| Windows AGY 账户适配 | 在上游仍拒绝 Windows 原生切换的范围内，增加 Windows Credential Manager 与私有文件权限适配。 | 已实现并验证过一次性测试凭据读写；真实双账户切换未实测。 |

这些功能建立在 Orca 的运行、任务、派发、终端、工作树和消息机制上。NASH 的差异是分类、选择和权限/验证规则，不是另造一套 CLI 会话与上下文传递系统。依据：决策 D-031、D-037、D-040 至 D-043，以及 checkpoint 的现行功能表。

## 2. 改动的功能与产品行为

| 功能 | 当前 NASH 行为 | 与原生的差异及边界 |
|---|---|---|
| 产品身份 | 使用 NASH 名称、应用 ID、用户数据目录、CLI 名称、用户提供的图标和独立仓库。 | 问题追踪与发布归 NASH；保留必要的原生插件与 RPC 标识。 |
| 界面与字体 | D12 Paper 暖色主题、语义颜色与间距、衬线/无衬线分工、随包 CJK 字体和六语言文案。 | 是 NASH 的视觉与信息组织变化；不代表所有继承界面都已重写。 |
| 设置组织 | 增加 Dot、任务路由分类；引导清单按 NASH 的实际能力与状态完成。 | 原有集成设置继续承担代码托管和任务提供方配置。 |
| 协调者称呼 | 原来界面中的 Primary/主代理统一使用 Coordinator/协调者。 | 本轮同步协调者 CLI、模型、推理强度、继承与会话相关文案。内部兼容标识不因此全量改名。 |
| 分类器称呼 | 原 Clef 设置标题与搜索名称改为 Classifier/分类器。 | 当前凭据与验证实现仍使用 Clef；未来其他分类模型尚未实现。 |
| 审核者编辑 | 每个审核者可直接编辑 CLI、模型、推理强度，并保存或取消。 | 本轮新增编辑入口；切换 CLI 会清空旧模型，要求重新给出具体模型 ID。 |
| 推理强度选项 | 协调者、任务及审核者按 CLI 和模型提供各自支持的选项。 | 本轮移除统一枚举的误导；使用已有 CLI/model 目录，不凭空增加能力。Claude、Codex、AGY 的选择范围可以不同。 |
| 已配置的项目工作流 | 工作流路由编辑只允许改模型，并保持工作流执行目标。 | 本轮收窄该行的编辑项；不能借此改成其他 CLI 或另设推理强度。 |
| 原生执行与上下文 | 新委派任务使用 Orca 原生 worker、派发、准备、消息、停止和释放；TaskSpec 的输出、验收与约束补入原生上下文。 | 本轮经分类/路由的 task-start 分支使用终端 CLI worker，让权限 hook 能到达协调者；普通原生 worker-start 仍遵循结构化聊天等原生默认选择，没有新增结构化审批桥。 |
| 子任务入口 | NASH 管理的任务经分类与 task-start；进一步委派交回协调者。 | 不允许从其他原生派发入口跳过 NASH 任务规则；原生 send/ask/reply/check 仍保留。 |
| 工作树策略 | 写入 Git 任务创建原生 child worktree；只读任务和普通文件夹保留原位置。 | 使用原生创建和合并机制，不复制未提交修改，不宣称有文件级锁。 |
| 运行取消 | 等待正在启动的 worker，并调用原生停止/释放；未确认停止会保留可见状态。 | Dot 接管的既有用户 CLI 不会被请求取消操作关闭；该操作明确拒绝，目前没有单独的解除接管入口。 |
| 工作流语言 | Dot、协调者及内部任务流程消息使用英文；工件语言服从任务本身。 | 已去掉固定 `zh-Hans` 交付约束和 `deliverableLanguage`。 |
| 插件来源 | 原生插件机制保留，官方 Orca catalog 与安全列表刷新由独立开关控制，默认关闭。 | 用户显式开启后沿用原生服务；本地插件、用户添加的来源及已安装插件继续工作。 |
| 全局状态 hooks | 自动安装范围仍限定为 Claude Code；其他 CLI 的启动能力保留。 | 本轮独立安装 Claude/Codex/AGY 权限 hooks，且只在身份可核对的 NASH 会话里转交审批；与状态 hooks 是不同链路。 |
| Windows/WSL | 保留开发服务 IPv4 绑定、WSL 冷启动预算和 NASH 身份路径适配等本地修复。 | 同时采用新版 Orca 运行时改进；不把全部 Windows 能力列为 NASH 新增。 |

审核者、推理强度和工作流编辑已通过定向 UI 测试。产品与原生复用依据见[当前 checkpoint](nash-checkpoint-2026-10-06.md)，界面规则见 [STYLEGUIDE](../desktop/docs/STYLEGUIDE.md)。

## 5. 本轮完成的协调者与权限适配

两种入口都保留：Dot 的新任务可自动启动协调者；已有原生 CLI 会话也可继续担任协调者，并由 Dot 显式接管指定运行。

| 功能 | 已实现行为 | 使用边界 |
|---|---|---|
| 接管已有原生协调者 | 为已经运行、身份可核对的 Claude/Codex 协调者绑定 NASH 分类、路由与审批元数据，复用同一 Run；保留 CLI、当前模型、上下文和既有任务历史。 | 当前支持本地 Claude/Codex 协调者；AGY 是受支持的 worker，未扩展为协调者。 |
| 运行切换与结束 | 没有待处理任务、派发或审批时允许协调者切换运行；只退出旧的 NASH 管理记录，用户已有 CLI 保持运行。 | 进程、pane 或运行绑定变化会使旧权限失效；未确认运行停止时不会冒充已经结束。 |
| Dot 接管指定既有运行 | `nash dot attach --workspace <ref> --run <runId> --objective-file <path>` 与本地 `dotIngress.requests.attach` 显式选择运行；远程 `nash_submit_task` 增加可选 `coordinatorRunId`。 | 不传该字段仍提交新任务。接管要求工作区与访问级别匹配；接管记录、请求及首条待发送消息原子落库，重复提交不会重启协调者。远程 Site 的源码和生成工件已更新，本轮未部署。 |
| Dot 授权与来源 | 原始运行来源保留，Dot 控制权单独记录；撤销全局或工作区授权、降低访问上限后，待发送消息也停止投递。 | 不将“曾经来自 Dot”当作永久授权；目前接管记录不提供独立的解除接管命令。 |
| CLI 分层权限审批 | Claude Code、Codex、AGY 的子任务普通审批交给协调者；协调者普通审批交给 Dot。核对实际进程、派发与运行身份，协调者不能自批，其他运行不能代批。 | 关键权限的脱敏摘要交给 Dot，并明确要求请求用户确认；Dot 不能批准关键权限，允许通过只能来自桌面用户，或退回 CLI 原生确认。未配置 Dot 时保留桌面/原生审批入口。 |
| Codex hook 信任 | 通过 Codex 自身列出的 hook 哈希核对 NASH 唯一精确匹配的权限 hook，再用原生配置接口授权并复查。 | 不授权其他用户 hook；版本不支持、定义变化、禁用或无法核对时记录固定原因，交由原生信任/审批流程处理。 |
| 任务路由高级后端删除 | 前后端专用高级功能均已删除；协调者、任务和审核者使用常规编辑与直接保存。 | 内部配置一致性机制保留，分类器的凭据、验证和运行保护保留。 |

接管是新增扩展方法；原 v3 hello 的方法枚举保持不变，避免旧客户端严格解析失败。新版 CLI 和本轮远程 bundle 可调用该方法；旧客户端不能据此自动获得接管能力。权限数据库从 v2 升到 v3，迁移保留旧审批记录、索引及序号，只增加协调者作为审批来源。

### 权限 hook 的激活边界

权限安装器在本地应用的 hook 初始化阶段写入 CLI 配置，等待 CLI 搜索路径就绪及原生状态 hook 写入完成；权限服务本身的安装不启动进程、不修改用户配置。Claude 沿用原生账户路由选择继承目录与现有账户目录；不是只向固定的 `~/.claude` 写入。某一提供方的配置损坏、不可读或在写入前被改动，不会阻止其他提供方和权限服务启动，原配置保留。守护脚本仅使用 NASH 会话提供的绝对 CLI 路径；脚本或应用不可用、或不在 NASH pane 内时，AGY 返回其原生 `ask`，Claude/Codex 留给原生权限界面。已输出的决定不会再追加回退答案。

配置写入不等于已运行会话立即采用它。新会话会按各 CLI 的原生规则加载 hook；已运行会话可能需要在 CLI 内检查、信任或刷新配置，NASH 不会为此自动重启既有 CLI。Claude 当前文档说明设置文件的 hook 变更通常由文件监视器自动拾取；Codex 的信任机制和 AGY 的实际加载状态仍需按所用版本验证，不能从配置文件存在推断为生效。[Claude hook 文档](https://code.claude.com/docs/en/hooks)、[Codex hook 文档](https://developers.openai.com/codex/hooks)、[AGY hook 文档](https://www.antigravity.google/docs/hooks/)。

这些安装与脚本测试只覆盖本地临时目录、假的 CLI 启动器和内存审批状态；没有更改真实 CLI 设置或宣称完成真实权限联调。SSH/WSL 不是本轮安装器已经覆盖的范围。AGY 的 `ask` 保留用户原有许可规则；已经进入 NASH 审批但未获决定时使用 `force_ask`，要求回到原生确认。[AGY 决策语义](https://www.antigravity.google/docs/hooks/)。

## 6. 不应继续列为当前差异的历史项目

- **“Claude Code 账户切换已移除”与“额度只取 CLI 输出”**属于较早决策。D-042 和当前 checkpoint 已记录恢复最新 Orca 的账户与额度实现；不能继续把 D-029/D-030 当作现状。Windows AGY 的本地适配仍是差异。
- **“Codex/AGY 任务总是只读、总走独立 headless 执行器”**已被后续写入权限与原生 worker 方案取代。独立复核的 one-shot 方式要单独描述。
- **“固定 Claude 是唯一协调者”**已过时；当前新运行可选择 Claude Code 或 Codex。
- **“排除整个 Gemini 4 家族”**已撤销；真实 provider 模型目录决定可用性，不提前声称未提供的型号可用。
- **“所有交付内容固定中文”**已撤销；内部流程使用英文，工件语言由任务要求决定。
- **“保留文件意味着功能仍启用”**不成立。更新、Orca Account/Mobile、RSI 和 Star 提示的关闭状态要单独说明。
